# Story 1.1: CAD Geometry Comparison - Core Comparison Workflow

## Status

Ready for Review

## Story

**As a** design reviewer,
**I want** to upload a CAD file (.stp format) and compare its geometric properties against a reference design from the library,
**so that** I can quickly identify dimensional differences between a new bottle design and an established reference without manual measurement.

## Acceptance Criteria

1. The user can upload a single .stp file via a web interface file upload control.
2. The application extracts the following geometric properties from the uploaded file using Python: overall length, width, height, bottle cap height, bottle cap width, bottle cap length, and any other detectable physical dimensions of the bottle geometry.
3. The user can select a reference design from a pre-populated library (previously uploaded STP or CSV-imported entries).
4. A comparison results page displays a 3-column table: **Property** | **Uploaded Design** | **Reference Design** — one row per geometric property.
5. The user can export the comparison results as a **PDF** file.
6. The user can export the comparison results as a **CSV** file.
7. Each completed comparison session is saved and retrievable by the user in a session history view.
8. The uploaded design is NOT automatically added to the reference library — it remains separate unless explicitly added by the user.

## Dev Notes

### Tech Stack
- No architecture documents exist yet for this project. Tech stack decisions to be made during architecture phase.
- Recommended candidates (to be confirmed by architect):
  - **Backend:** Python (Flask or FastAPI)
  - **STP Parsing:** pythonocc-core (Open CASCADE) or cadquery — both support STEP/STP geometry extraction
  - **PDF Generation:** 
eportlab or weasyprint
  - **Database:** SQLite (local/simple) or PostgreSQL
  - **Frontend:** Simple HTML/JS or lightweight framework (e.g., HTMX or React)

### Key Constraints
- **Multi-user shared system** — reference library and session history visible across organization
- File format is strictly `.stp` (STEP format) — parser must handle ISO 10303-21
- Geometric properties to extract: overall length, width, height; bottle cap length, width, height; additional detectable physical dimensions
- Uploaded designs must remain isolated from the reference library unless explicitly promoted
- File uploads must be stored in Azure Blob Storage, not on app server filesystem
- Database must support concurrent access from multiple users via Azure PostgreSQL

### Out of Scope for This Story
- Populating the reference library (separate story needed)
- Importing reference designs via CSV (separate story needed)
- User authentication / access control

  - Unit tests for export generation (PDF/CSV output not empty, correct columns)
  - Integration test for full upload → compare → export flow
