# Story 1.3: Reference Library - Import Designs via CSV

## Status

Draft

## Story

**As a** design reviewer,
**I want** to import a CSV file containing known geometric property values into the reference library,
**so that** I can quickly populate the library from existing data without uploading individual STP files.

## Acceptance Criteria

1. The user can upload a .csv file from the Reference Library section.
2. The application validates the CSV format: required columns must include design name, length, width, height, bottle cap length, bottle cap width, bottle cap height. Additional columns are stored as-is.
3. If the CSV is invalid or missing required columns, the user sees a clear error message identifying the problem.
4. Valid rows are imported and saved to the reference library database.
5. The user is shown a summary after import: number of rows successfully imported, number of rows skipped (with reasons, e.g., duplicate name, missing values).
6. Rows with duplicate names prompt the same overwrite-confirmation behavior as Story 1.2 (warn and confirm before overwriting).
7. All successfully imported designs appear in the reference library list.

## Tasks / Subtasks

- [ ] Add CSV upload control to Reference Library page (AC: 1)

- [ ] Reflect imported entries in library list (AC: 7)

## Dev Notes

- Depends on Story 1.2 being complete — reference library database table and duplicate-check logic must exist

### CSV Format (Expected)
| Column | Required | Notes |
|--------|----------|-------|
| name | Yes | Unique design identifier |
| length | Yes | Numeric, mm |
| width | Yes | Numeric, mm |
| height | Yes | Numeric, mm |
| cap_length | Yes | Numeric, mm |
| cap_width | Yes | Numeric, mm |
| cap_height | Yes | Numeric, mm |
| (any others) | No | Stored as metadata |

### Key Constraints
- **Multi-user shared system** — imported designs added to shared reference library for all users
- CSV must be validated server-side — do not trust client-side validation alone
- Duplicate handling must be consistent with Story 1.2 behavior — flag duplicates, do not silently overwrite
- **Database:** Azure PostgreSQL with concurrent write protection for batch imports
- **Architecture decisions pending:** Tech stack to be confirmed during architecture phase

### Out of Scope for This Story
- Exporting the reference library as CSV (post-MVP)
- Editing individual library entries via CSV re-import
- User authentication / access control

### Testing
- Unit test: valid CSV imports all rows correctly
- Unit test: CSV missing required column returns correct error
- Unit test: duplicate name row flagged in summary, not silently overwritten
- Integration test: upload CSV → import → all entries appear in library list
